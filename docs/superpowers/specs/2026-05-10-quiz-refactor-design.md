# Дизайн рефакторинга: интервью → квиз без бэкенда

Дата: 2026-05-10

## Контекст и причина

Приложение пойдёт на модерацию SmartApp Studio, и там нельзя держать собственный
сервер. Текущая реализация использует FastAPI + GigaChat для оценки голосовых
ответов — это исчезает целиком. Голосовое интервью со свободным ответом превращается
в офлайн-квиз с выбором одного правильного варианта из четырёх (multiple choice).

Темы — те же: Python, Classical ML, Deep Learning, NLP/CV. Радар-чарт результатов
тоже остаётся.

## Цели и не-цели

**Цели:**
- Убрать `backend/` целиком; всё работает в собранном фронте без сетевых запросов.
- Перевести прохождение в формат MCQ: 4 варианта на вопрос, один правильный.
- Сохранить голосовое управление как первичный способ ввода (пульт SberBox).
- Дать выбирать длину прохождения (5 / 10 / 20 / весь банк).
- Показывать мгновенный фидбек после ответа: подсветка верного и неверного варианта,
  текстовое объяснение.
- Накопительный радар-чарт по нескольким темам в одной сессии.

**Не-цели:**
- Хранение истории прохождений между запусками (нет storage).
- Аналитика, телеметрия, отправка результатов куда-либо.
- Рандомизация порядка вариантов внутри вопроса (порядок задан в банке).
- Адаптивная сложность.

## Поток пользователя

1. **Welcome.** 4 карточки тем. Голос: «Запусти Python», «Выбери третью тему».
2. **LengthPick.** 4 кнопки: 5 / 10 / 20 / Все. Голос: «Пять вопросов», «Весь банк».
3. **Quiz.** Вопрос + 4 варианта (1..4). Озвучка вопроса и каждого варианта.
   Голос: «Первый», «Вариант два», «Не знаю». Кнопки 1..4 + «Не знаю» + «Закончить».
4. **Feedback.** На том же экране: правильный вариант подсвечен зелёным,
   выбор пользователя — зелёным (если совпал) или красным (если ошибся).
   Под вопросом — текст-объяснение, он же озвучивается. Голос: «Дальше», «Закончить».
   Автоперехода по таймеру нет.
5. После N вопросов — `radarScores[topic] = correctCount / N`. Переход в Result.
6. **Result.** Радар по 4 темам (непройденные — пустые). Кнопки: «Пройти ещё тему»
   (→ Welcome, радар сохраняется) и «Начать заново» (полный сброс радара).

«Не знаю» = моментальный фидбек на правильный вариант, ответ засчитывается как
неверный.

«Закончить» из Quiz/Feedback = досрочный финиш темы, оставшиеся вопросы не зачёт,
радар обновляется по уже отвеченным.

`App` остаётся class-компонентом — это требование CLAUDE.md (ассистент инициализируется
в конструкторе и не должен переезжать в хуки). `App` ничего не считает сам: получает
action от ассистента или клика, вызывает соответствующую функцию `quizEngine`,
кладёт результат в `setState`.

### State

```js
{
  status: 'welcome' | 'length-pick' | 'quiz' | 'feedback' | 'results',
  currentTopic: 'python' | 'classical_ml' | 'deep_learning' | 'nlp_cv' | null,
  questionPlan: Question[],     // выбранные на этом прохождении вопросы по порядку
  questionIdx: number,           // индекс текущего в questionPlan, 0..N-1
  selectedOption: number | null, // 0..3 после обычного ответа, null до ответа и при «не знаю»
  dontKnow: boolean,             // true, если на этом вопросе пользователь сказал «не знаю»
  correctCount: number,          // правильные ответы в текущей теме
  radarScores: {
    python:        number | null,  // доля правильных, 0..1, или null если не проходили
    classical_ml:  number | null,
    deep_learning: number | null,
    nlp_cv:        number | null,
  },
}
```

### quizEngine API

Все функции — чистые: принимают state и параметры, возвращают новый state.
Никаких побочных эффектов, никаких ссылок на React/ассистента.

```js
initial(): State
chooseTopic(state, topic): State              // welcome → length-pick
chooseLength(state, length): State            // length-pick → quiz, сэмплит вопросы
pickAnswer(state, optionIdx): State           // quiz → feedback (correctCount++ если верно)
markUnknown(state): State                     // quiz → feedback с dontKnow=true, selectedOption=null
nextQuestion(state): State                    // feedback → quiz | results
finishTopic(state): State                     // quiz/feedback → results, обновляет radarScores
restart(state): State                         // results → welcome, radarScores сохраняется
resetAll(state): State                        // results → welcome, radarScores обнуляется
```

`length` ∈ `5 | 10 | 20 | 'all'`. Если в банке темы меньше N — берётся всё, что есть.

Сэмплинг — Fisher-Yates над копией массива вопросов. Источник случайности —
параметр-функция (по умолчанию `Math.random`), чтобы тесты могли инжектить детерминизм.

### getStateForAssistant

Динамически зависит от `state.status`:

| status        | items                                              |
|---------------|----------------------------------------------------|
| welcome       | 4 темы (как сейчас)                                |
| length-pick   | 4 длины: «5 вопросов», «10 вопросов», «20 вопросов», «весь банк» |
| quiz          | 4 варианта ответа, title = текст варианта          |
| feedback      | items пустой; навигация через action_id            |
| results       | items пустой                                       |

Распознавание «первый/второй/третий/четвёртый» обеспечивает item_selector Салюта —
руками парсить не нужно.

## Формат банка вопросов

```js
// src/data/questions.js
export const QUESTIONS = {
  python:        [Question, ...],
  classical_ml:  [Question, ...],
  deep_learning: [Question, ...],
  nlp_cv:        [Question, ...],
};
```

```ts
type Question = {
  id: string;            // стабильный идентификатор, формат "<topic-prefix>-<slug>-NNN"
  text: string;          // формулировка вопроса
  options: [string, string, string, string];
  correct: 0 | 1 | 2 | 3;
  explanation: string;   // 1–2 предложения, идёт и на экран, и в TTS
};
```

Дополнительные правила:
- `options` всегда длина 4 — проверяется тестом банка.
- `correct` — целое число 0..3 — проверяется тестом банка.
- `id` уникален в пределах темы — проверяется тестом банка.
- Никаких HTML/markdown в `text`/`options`/`explanation` — только plain text
  (TTS должен корректно прочитать).

Контент-наполнение происходит вне кода имплементации: переписываются ~150
существующих открытых вопросов из `backend/questions.py` в MCQ-форме, по 35 на тему
(точное число — сколько получится из текущего банка).

## .sc-сценарии

`smartapp-backend/src/` переписывается под новые intent-ы. Архив `scenario-new.zip`
обновляется и заливается в SmartApp Studio.

| Action на фронт   | Голосовые формулировки                      | Где принимается   |
|-------------------|---------------------------------------------|-------------------|
| CHOOSE_TOPIC      | «выбери Python», «начни DL», «третья тема»  | welcome           |
| CHOOSE_LENGTH     | «пять вопросов», «двадцать», «весь банк»    | length-pick       |
| PICK_OPTION       | «первый», «вариант два», «номер три»        | quiz              |
| DONT_KNOW         | «не знаю», «пропусти»                       | quiz              |
| NEXT_QUESTION     | «дальше», «следующий»                       | feedback          |
| FINISH_QUIZ       | «закончить», «хватит»                       | quiz / feedback   |
| START_AGAIN       | «начать заново», «ещё одну тему»            | results           |

`PICK_OPTION` использует штатный механизм item_selector: Салют сам мапит «первый» →
номер 1 и присылает соответствующий action.

Action `SPEAK` (TTS-озвучка) остаётся как есть — обрабатывается узлом «Озвучить»
в .sc.

## Тестирование

**Unit:**
- `quizEngine.test.js` — каждый переход (welcome→length-pick→quiz→feedback→...),
  корректность `correctCount` и `radarScores`, поведение на границах
  (последний вопрос → results, length=all, банк короче запроса).
- `questions.test.js` — структурная валидация банка.

**Ручной прогон в dev (через `createSmartappDebugger`):**
- Прохождение полного цикла одной темы с голосом.
- «Не знаю» в середине прохождения.
- «Закончить» в середине — проверить, что радар обновился по отвеченным.
- Прохождение второй темы подряд — радар накапливается.
- «Начать заново» из results — радар обнуляется.
